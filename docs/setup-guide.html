VoiceForge — complete setup guide

From an empty Vercel account to generating narration in your own cloned voice from n8n. Follow it top to bottom the first time; after that you only ever repeat Reconnecting.

What you're building

Three pieces, each free:

The web app

Next.js on Vercel. Studio, admin panel and public API. Has no GPU — it never runs a model.

Storage

One Supabase project: Postgres for settings, keys, jobs and the backend registry, and a storage bucket for voice clips and finished audio.

A GPU backend

Colab, Kaggle or Modal running the speech model. It registers itself with your app.

The important idea: you never copy a tunnel URL. The notebook tells the app where it is and keeps a heartbeat going. The app picks whichever backend is healthy when a request arrives.

1Deploy to Vercel

  1. Fork bijaybista006-art/voiceforge on GitHub (skip if it's already yours).
  2. Go to vercel.com/new → import the repo.
  3. Framework preset Next.js. Leave everything else alone.
  4. Click Deploy and wait for the build.
  5. Note your URL, e.g. https://audio.example.com. You'll paste it into the notebook later.

The app works with nothing configured. It'll tell you what's missing rather than crash. That's deliberate — you can never lock yourself out of your own deployment.

2Add storage

Supabase

  1. supabase.com → New project. Free plan; pick the region closest to you.
  2. SQL Editor → New query → paste all of supabase/migrations/0001_voiceforge_storage.sql → Run.
  3. Project Settings → API: copy the project URL, the anon key and the service-role key.
  4. Vercel → your project → Settings → Environment Variables: add NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY, then redeploy.

The bucket is public on purpose. Your GPU backend downloads the voice clip straight from its URL with no token, and the browser plays it the same way. Private would break both. File paths carry random ids, so they aren't guessable.

The service-role key is a secret. It bypasses every access rule. It belongs in Vercel's environment variables and your own .env.local — never in a notebook, in Modal, or in a variable whose name starts with NEXT_PUBLIC_.

The full walkthrough, including a script that checks the project is set up correctly, is in docs/supabase-setup.md.

3Add secrets

Generate two long random strings:

node -e "console.log('REGISTRATION_TOKEN=' + require('crypto').randomBytes(24).toString('hex')); console.log('BACKEND_SECRET=' + require('crypto').randomBytes(24).toString('hex'))"

Add both in Settings → Environment Variables, ticked for Production, Preview and Development:

VariableWhat it does
REGISTRATION_TOKENA notebook must present this to register itself. Stops a stranger pointing your app at their machine.
BACKEND_SECRETShared secret the app sends to your GPU on every call. The backend rejects anything else.

Never commit these. In particular, if you press Colab's Save a copy in GitHub after filling in Cell 0, your secrets go into the repo. If that happens, rotate both values in Vercel — that makes the leaked pair worthless immediately.

Then redeploy: Deployments → top entry → ⋯ → Redeploy. Environment variables only reach the app on a fresh build.

4Admin login (optional but recommended)

Until you set these, your site is public. Add both to turn the gate on:

VariableValue
ADMIN_PASSWORDWhatever you'll type at the login screen.
SESSION_SECRETAnother long random hex string. Rotating it signs out every session.

Redeploy, then visit /login. The session lasts 12 hours.

The gate only activates when both exist. One without the other leaves the app open — that's a safety valve, not a bug.

Connect Google Colab

  1. In your app, open Admin → Backends and click Open in Colab. (Direct link below if you prefer.)
  2. Runtime → Change runtime type → T4 GPU → Save. Without this nothing works.
  3. Store your three values as Colab Secrets — once, not every session. Click the key icon in the left sidebar and add: 
    VOICEFORGE_APP_URL   https://your-app.vercel.app
REGISTRATION_TOKEN   the value you set in Vercel
BACKEND_SECRET       the other value you set in Vercel
    Toggle Notebook access ON for each. Cell 0 reads them automatically and you never edit the notebook again.

    This also protects you. Secrets typed into Cell 0 get committed if you ever press Colab's Save a copy in GitHub — which has happened. Secrets stored this way never touch the notebook file.

  4. Run Cell 0, then Cell 1. Cell 1 takes 3–10 minutes and prints a wall of red pip conflict lines about jax, opencv and cupy — expected and harmless; that's Colab's preinstalled data-science stack, which this backend never imports.
  5. Runtime → Restart session. This is required: the kernel is still holding the numpy it imported at startup.
  6. Run Cell 0 again, then Cell 2. It should end with models ready: ['chatterbox'].
  7. Run Cell 3. It opens a tunnel and registers itself.

Open the notebook in Colab

Success looks like this:

tunnel: https://some-words-here.trycloudflare.com
==============================================================
  REGISTERED — nothing to copy. Check Admin -> Backends.
  provider: colab   heartbeat: every 60s
==============================================================

Within about a minute the Colab card in Admin → Backends turns Online. Press Test to confirm it answers.

Leave the Colab tab open. Close it and the backend dies. The tunnel URL is different every session — you never see it, because the notebook re-registers and heartbeats every 60 seconds.

Connect Kaggle

Same notebook, and you can keep it running alongside Colab as a second free GPU.

  1. Go to kaggle.com/code → New Notebook → File → Import Notebook → paste the GitHub URL of colab/voiceforge_server.ipynb.
  2. Right panel → Accelerator → GPU T4 x2.
  3. Right panel → Internet → On. Without this nothing works: pip can't reach PyPI, the model never downloads, and the notebook can't register.

    Kaggle only shows this toggle on a phone-verified account. If Internet is greyed out, go to kaggle.com/settings → Phone Verification, verify, then reopen the notebook.

  4. Add-ons → Secrets — add VOICEFORGE_APP_URL, REGISTRATION_TOKEN and BACKEND_SECRET, and attach each to the notebook. Leave Cell 0 untouched; it reads them automatically, this session and every future one.
  5. Run Cell 0 → Cell 1 → restart the session → Cell 0 → Cell 2 → Cell 3, exactly as for Colab.

Kaggle gives you 30 GPU-hours a week and longer sessions than Colab. Your voice library is shared, so a voice added anywhere works on both.

Connect Modal (the always-on option)

Modal gives you a permanent HTTPS URL that scales to zero — no tab to keep open, and nothing to press. This is what makes unattended n8n workflows practical.

  1. Sign up at modal.com. The free credit (about $5/month) covers light use, and no card is required.
  2. Install and authenticate: 
    pip install modal
modal token new
  3. Give Modal the same backend secret you put in Vercel: 
    modal secret create voiceforge-backend BACKEND_SECRET=<your BACKEND_SECRET>
  4. Deploy from inside the repo: 
    modal deploy modal/voiceforge_modal.py
    It prints a URL ending in .modal.run.
  5. In Admin → Backends, find Modal under “Not connected yet”, paste that URL, and press Add.
  6. Leave Active backend on Auto and check Modal sits last in the order (it shows “last resort”). Use the ↓ button if it doesn't.

Modal as a pure fallback. With that ordering, every job goes to Colab or Kaggle while either is running, and Modal is only woken when both are offline. Since Modal bills per second and sleeps at zero, an untouched fallback costs nothing.

Modal never heartbeats, by design. It has a permanent URL and scales to zero, so it is not aged out the way a Colab tunnel is — a quiet Modal still counts as available. Colab and Kaggle go Offline after three missed heartbeats; Modal doesn't.

Automatic redeploys (optional)

The repo ships a GitHub Action that redeploys Modal whenever backend/ or modal/ changes. Add two repository secrets under Settings → Secrets and variables → Actions:

SecretWhere from
MODAL_TOKEN_IDPrinted by modal token new, or Modal dashboard → Settings → API Tokens
MODAL_TOKEN_SECRET

Cold starts. After ~2 minutes idle, Modal shuts the GPU down. The next request waits roughly a minute while it wakes. That's why every API endpoint except /audio/speech is asynchronous — see The API.

Health checks are served by a separate CPU-only function, so the admin page polling status never wakes the GPU or burns credit.

Connect a custom backend

Anything that implements the contract works: your own server, a rented GPU, a different tunnel. In Admin → Backends, paste the URL under Custom URL → Add. It must send the same BACKEND_SECRET and implement:

MethodPathPurpose
GET/healthStatus, GPU name, loaded models, busy flag
PUT/voices/{id}Download and cache a reference clip
POST/generateOne chunk; answer 409 voice_not_cached if unknown
POST/jobsBackground render of a whole script
GET/jobs/{id}/audio/{n}Hand back a finished file

The reference implementation is backend/voiceforge_server.py — the same file Colab, Kaggle and Modal all run.

Switching and fallback

At the top of Admin → Backends you choose what's active:

  • Auto — use the first healthy backend in the listed order. Default is Colab → Kaggle → Custom → Modal: free GPUs first, paid last, so Modal only picks up work when the notebooks are genuinely down. Reorder any card with the ↑ ↓ buttons.
  • A specific provider — pin everything to that one. If it's offline, requests fail with a clear message rather than quietly going elsewhere.

A backend is marked Offline after three missed heartbeats (about three minutes). Disable keeps a backend registered but out of rotation, and that choice survives the notebook re-registering.

5Add your voice

Go to Admin → Voices (or use the Voice panel in the studio).

  1. Record or upload 15–20 seconds of clean speech — quiet room, no music, natural pace. A phone mic is fine.
  2. Type the transcript: exactly what's said, word for word. This matters more than you'd expect; the clone is noticeably worse without it.
  3. Pick the language, name it, and save.

Clone once, forever. The clip is stored centrally and cached onto whichever GPU is running the first time it's used. A Colab restart, a switch to Modal, a different browser — none of them need a re-clone.

The first voice you add becomes the default, which is what API calls use when they don't name one.

Ethics, and this isn't a formality. Clone your own voice, or one you have explicit permission to clone. In most jurisdictions synthesising someone's voice without consent is illegal, and it's a genuinely harmful thing to do regardless.

6Make narration in the studio

  1. Open the app root and choose Text to Speech.
  2. Paste your script, or drop in a .txt / .md file. It's split into chunks automatically — check the split before generating.
  3. Pick your voice and language. Adjust expressiveness only if you need to; the defaults are tuned for narration.
  4. Press Generate. Chunks render one at a time and each is saved the moment it finishes.
  5. Export as WAV, MP3 or SRT.

If the GPU disappears mid-run, everything already generated is kept. Start the backend again and resume — nothing is lost.

7Create an API key

  1. Admin → API Keys.
  2. Name it after the thing that will use it, e.g. n8n. One key per integration means you can revoke one without breaking the others.
  3. Optionally set requests per minute and a monthly character quota. Blank means the default (60/min, unlimited characters).
  4. Press Create key and copy it now.

Shown once, never again. Only a SHA-256 hash is stored, so a lost key can't be recovered — revoke it and make another. Revoking takes effect on the very next request.

8The API

Base URL is https://your-app.vercel.app/api/v1. Every request carries:

Authorization: Bearer vf_live_…
MethodEndpointDoes
GET/voicesList your voices and which is default
POST/ttsText → one stitched narration. Returns a job id.
POST/tts/batchMany lines → one clip each, not stitched
GET/jobs/{id}Poll a job
POST/audio/speechOpenAI-compatible, synchronous, ≤600 characters

Why everything is asynchronous. A Vercel function is capped at 60 seconds, and a cold Modal container can use most of that before it speaks a word. So /tts hands back a job id immediately and the render continues on the GPU. Only /audio/speech is synchronous, which is exactly why it's capped at 600 characters.

Start a job

curl -X POST https://your-app.vercel.app/api/v1/tts \
  -H "Authorization: Bearer $VOICEFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from VoiceForge.","format":"mp3"}'
{
  "job_id": "8f1c…",
  "status": "running",
  "status_url": "https://your-app.vercel.app/api/v1/jobs/8f1c…",
  "chars": 24,
  "chunks": 1,
  "backend": "modal"
}

Poll it

curl https://your-app.vercel.app/api/v1/jobs/8f1c… \
  -H "Authorization: Bearer $VOICEFORGE_KEY"
{
  "job_id": "8f1c…",
  "status": "done",
  "duration": 2.4,
  "audio_url": "https://….supabase.co/storage/v1/object/public/voiceforge-audio/jobs/8f1c….mp3"
}

audio_url is an ordinary HTTPS file — download it with any HTTP client. It's deleted after the retention window in Settings (7 days by default).

Request options for /tts

FieldMeaning
textRequired. Up to 50,000 characters.
voice_idOptional. Defaults to your default voice.
languageOptional ISO code, e.g. en, hi. Defaults to the voice's language.
formatmp3 (default) or wav.
callback_urlOptional. We POST the finished job here instead of you polling.

9n8n — the polling workflow

This works on every n8n, including n8n Cloud, because VoiceForge never has to reach back to you.

Credential (do this once)

  1. Credentials → New → Header Auth.
  2. Name: Authorization
  3. Value: Bearer vf_live_… (include the word Bearer and a space)

Nodes

  1. HTTP Request — name it Start TTS
    • Method POST, URL https://your-app.vercel.app/api/v1/tts
    • Authentication → Generic Credential Type → Header Auth → the credential above
    • Send Body → JSON:
    {
  "text": "{{ $json.script }}",
  "format": "mp3"
}
  2. Wait — 10 seconds.
  3. HTTP Request — name it Check Job
    • Method GET, same Header Auth credential
    • URL:
    {{ $('Start TTS').item.json.status_url }}
  4. IF — condition: {{ $json.status }} equals done.
    • false branch → back to the Wait node (that's the loop)
    • true branch → continue
  5. HTTP Request — name it Download Audio
    • Method GET, URL {{ $json.audio_url }}
    • No authentication — it's a public file URL
    • Response → Format: File

You now have the MP3 as binary data, ready for Google Drive, Telegram, an FFmpeg node, or wherever it's going.

Handle failure too. Add a second IF for {{ $json.status }} equals error and branch to a notification — {{ $json.error }} carries the reason in plain words.

10n8n — the callback workflow

Fewer nodes, no polling. Needs an n8n your app can reach over the internet (n8n Cloud is fine; a laptop behind NAT is not).

  1. Add a Wait node, set Resume → On Webhook Call.
  2. Before it, an HTTP Request → POST /api/v1/tts with the Header Auth credential and: 
    {
  "text": "{{ $json.script }}",
  "format": "mp3",
  "callback_url": "{{ $execution.resumeUrl }}"
}
  3. When the render finishes, VoiceForge POSTs the finished job to that URL and n8n wakes up with the body: 
    {
  "job_id": "8f1c…",
  "status": "done",
  "duration": 92.5,
  "audio_url": "https://….mp3"
}
  4. Then HTTP Request → GET {{ $json.audio_url }}, Response Format File.

The callback is best-effort, and that's safe. Polling /jobs/{id} still works as a fallback, because a poll re-checks the backend and finishes the job itself. A tunnel that dies between “render finished” and “POST sent” costs you a poll interval, not the render.

11n8n — batch (one clip per line)

For reels and short-form, where every scene needs its own audio file.

curl -X POST https://your-app.vercel.app/api/v1/tts/batch \
  -H "Authorization: Bearer $VOICEFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "items": [
      { "text": "Scene one." },
      { "text": "Scene two." },
      { "text": "Scene three." }
    ]
  }'

Poll the same way. The finished job has an items array instead of one audio_url:

{
  "status": "done",
  "items": [
    { "index": 0, "duration": 1.4, "audio_url": "https://…-0.mp3" },
    { "index": 1, "duration": 1.5, "audio_url": "https://…-1.mp3" },
    { "index": 2, "duration": 1.6, "audio_url": "https://…-2.mp3" }
  ]
}

In n8n, feed items into a Split Out node (field: items), then an HTTP Request on {{ $json.audio_url }} with Response Format File. You get one binary item per scene.

Limits: up to 50 items, 2,000 characters each.

12OpenAI-compatible endpoint

Point any OpenAI TTS client at your base URL and it works — same request shape, same raw-audio response.

curl -X POST https://your-app.vercel.app/api/v1/audio/speech \
  -H "Authorization: Bearer $VOICEFORGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"tts-1","input":"Short and synchronous.","response_format":"mp3"}' \
  --output speech.mp3
  • Returns audio bytes, not JSON.
  • Capped at 600 characters, because it must finish inside one request.
  • voice takes a VoiceForge voice id. An unknown name falls back to your default, so clients that insist on sending alloy still work.
  • model is accepted and ignored — your model comes from the library and the live backend.

If your only backend is Modal and it's cold, this can exceed 60 seconds and time out. For unattended work prefer /api/v1/tts.

Reconnecting after a session ends

Colab and Kaggle sessions expire. When one does, the tunnel dies, heartbeats stop, and the app marks it Offline after about three minutes.

  1. Admin → Backends → Open in Colab (or Kaggle).
  2. Check the GPU is still T4.
  3. Re-paste Cell 0 if it was cleared. Kaggle Secrets users skip this.
  4. Cell 0 → Cell 1 → Restart session → Cell 0 → Cell 2 → Cell 3.

Nothing else to redo. New tunnel, registered automatically. Your voices, API keys and job history are on the server and untouched. No re-cloning, ever.

If you'd rather never do this: use Modal.

Troubleshooting

SymptomCause & fix
“Finish setup before backends can register” Redis missing or REGISTRATION_TOKEN unset. Add them, then redeploy — env vars only apply to a new build.
Storage says not connected although you added it You almost certainly haven't redeployed since. If it persists, check the variable names exist in Settings → Environment Variables.
Voices page: “Storage isn't ready” The Supabase variables are missing or the project is paused. Check all three exist in Settings → Environment Variables, and that the project is active in the Supabase dashboard.
Kaggle: Temporary failure in name resolution, No matching distribution, cannot access archive That session has no internet — all three are the same cause. Right panel → Session options → Internet → On. If the toggle is greyed out, phone-verify at kaggle.com/settings first.
Cell 1 ends shared server downloaded: 0.0 KB The repo is private, so raw.githubusercontent refused it. Make the repo public, or upload backend/voiceforge_server.py into the notebook by hand.
numpy is 2.5.3, need 2.2.x or Numba needs NumPy 2.2 or less Re-run Cell 1, then Runtime → Restart session, then Cell 0 and Cell 2. The kernel was holding the numpy it imported at startup.
AssertionError: No GPU Runtime type isn't T4. Colab: Runtime → Change runtime type. Kaggle: Accelerator → GPU T4 x2.
REGISTRATION FAILED in Cell 3 Wrong VOICEFORGE_APP_URL or REGISTRATION_TOKEN. The backend is still running — you can add the printed URL under Backends → Custom as a stopgap.
Backend shows the wrong provider name Old notebook version. Reload it from the repo; detection now uses google.colab and Kaggle's own env vars.
API returns 503 no_backend Nothing is online, or you pinned a provider that's down. Start a notebook, or set Active backend to Auto.
Job stuck on running Poll it once more, or open Admin → Jobs — both re-check the backend and will finish it or report the real error.
Job errors with “the backend restarted” The GPU session ended mid-render. Start it again and resubmit.
Red pip conflict wall in Cell 1 Expected. That's Colab's preinstalled stack, which this backend never imports. Only an AssertionError at the end of Cell 1 matters.

The honest limits

  • Colab free gives a few hours per session and has a daily cap. Plenty for a video or two a day; not enough to run a service on.
  • The Colab/Kaggle tab must stay open while you generate. Modal is the only unattended option.
  • Generation is sequential — one chunk at a time, because it's one GPU. Two jobs queue behind each other.
  • Nepali uses its own model. The base Chatterbox Multilingual model covers 23 languages and Nepali is not one of them, so Nepali runs on a separate fine-tuned checkpoint that loads the first time you use it. The first Nepali request on a fresh backend is slow while it downloads.
  • Number expansion is English-only. “15GB” becomes “fifteen gigabytes” in English scripts; other languages keep the digits for the model to read in-language.
  • Generated audio is deleted after the retention window in Settings — 7 days by default. Download anything you want to keep.
  • Your voice sample goes from your browser to your Supabase bucket and from there to your GPU. Not to Anthropic, not to any TTS company.
