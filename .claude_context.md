# Context Map — VoiceForge

updated: 2026-11-02 | commit: 12be38a

Voice cloning + long-form narration studio, plus presenter video and AI video
clips. Next.js app on Vercel; GPU inference on backends you connect (free
Colab/Kaggle notebooks that self-register, or paid Modal).

Read this file first. It is the index: where things are, not why. The *why*
— every design decision, constraint and piece of history — lives in
`.claude_context/notes.md`; read a dotted part below before editing in that
area.

## Stack
- runtime: Next.js 15 (App Router) / TypeScript, React 19, Tailwind, Zustand
- backend: FastAPI (Python), one `backend/voiceforge_server.py` shared by
  Colab, Kaggle and Modal — see `.claude_context/backend.md`
- storage: Supabase only (Postgres `kv` table + one public bucket) — never
  Vercel Blob/Upstash, never env-var backend URLs
- deploy: Vercel (frontend, auto on push to `main`), Modal (`modal deploy`,
  also via `.github/workflows/deploy-modal.yml`)
- test: `npm test` (vitest, `lib/__tests__/`, `components/__tests__/`),
  `npm run test:e2e` (Playwright, `e2e/*.spec.ts`), `npm run lint`,
  `npm run typecheck`; `pytest backend/tests` (no GPU, no network)

## Conventions
- The browser NEVER calls a GPU backend directly. `lib/server/gateway.ts` is
  the only place that knows a backend URL or `BACKEND_SECRET`.
- Backend URLs live in server-side storage (self-registered, or typed into
  Admin). Never hardcoded, never an env var.
- A render NEVER travels in a request/callback body (Vercel's 4.5 MB cap).
  Backends write to disk, POST metadata only, the gateway pulls the file —
  see notes.md "Job contract".
- Generation is sequential on a shared GPU: one `_GPU_LOCK` per backend
  process. AI video and presenter share a second `_ENGINE_LOCK` so they take
  turns on a two-GPU Kaggle session. Lock order everywhere: own → engine →
  voice.
- Theme colours are CSS-variable tokens (`bg-surface`, `text-muted`, …) —
  never hardcode `bg-white`/hex in a component. See notes.md "UI v2".
- `signal`/`live` (amber) is ONLY for actively recording/generating. Never a
  button colour.
- Routing order is fixed: Colab → Kaggle → Custom → Modal, first usable
  wins. The stored `active` pin and `priority` are NOT read by routing
  (`lib/routingView.ts`) — they're legacy preferences, shown as such.

## Gotchas
! MAX_CHARS = 240/chunk is load-bearing — longer chunks make both TTS models drift
! No Supabase env ⇒ features report "not connected", never crash; `middleware.ts`
  only gates auth when BOTH `ADMIN_PASSWORD` and `SESSION_SECRET` are set — an
  unconfigured deploy must stay open, don't "fix" this by gating unconditionally
! Voice clips server-side are ALWAYS 16-bit PCM WAV — browser re-encodes before
  upload; don't accept MP3 server-side (libsndfile build varies per host)
! `backendFeatures()` (lib/server/backends.ts) is the ONLY place that reads the
  per-backend Voice/Presenter/AI-video switches — don't re-derive them
! Modal's Wan app URL and the voice app URL have different forms (region vs
  not) — `wanCandidateUrls` tries several; don't collapse to one derived URL
! A notebook's AI video install needs ~42 GB free disk next to the voice
  model; `ensure_space()` refuses rather than filling the disk — see
  notes.md "AI video clips"
! `backend/wan/engine.py` is the only backend file allowed to import torch at
  module level; everything else must import clean for CI's no-GPU tests
! Icons are hand-written inline SVG in `components/ui/Icons.tsx` — no icon
  library, nothing fetched externally
